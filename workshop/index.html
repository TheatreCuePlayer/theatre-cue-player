Q10:00–0:03

Why this exists

Say

Who you are and where you teach. One sentence on the problem: if your crew still presses play in a music app, you've felt the gap between that and real show control. Don't re-argue why playback software matters; this room already came for it.

The frame: it's a classroom training tool. You still run your productions on professional software. Every word in TCP (cue, GO, fade cue, auto-follow, target, surface) is the industry's word, on purpose, so students recognize what they're looking at when they sit down at QLab.

The story: in your last show, students built a rehearsal show in TCP, then the sound crew built the real show in QLab. The TCP version was how they learned; QLab was the performance.

Q20:03–0:08

Two versions, pick one

Say

Extension: the full thing. Audio, video, projection mapping, text cues, second-screen output, the sound editor, backups, optional Google Drive. Installs from the Chrome Web Store.

Browser version: audio only, nothing to install. Opens from a link or runs off a USB stick, no admin rights, no internet. It's the one that still works where districts block extensions.

Both run in Chrome on a Chromebook, Windows or Mac. Invite them to install along with you now, and keep going while they do.

Screen

Homepage, "Two ways to run it". Then the Web Store listing.

Do

Click Add to Chrome on the listing (you already have it; show the button and the permission prompt, or remove and re-add if the Wi-Fi is good). Then open the browser-version link in a new tab.

Pitfall: school Chromebooks

On district-managed Chromebooks, students often can't install extensions at all. IT can allow it, or push it to every student device, from the Google Admin console. Ask IT weeks before the unit, not the morning of. Until then, the browser version needs no permission from anyone.

If asked early: "Does it work on iPads?" No. It needs Chrome on a laptop or Chromebook.
Q30:08–0:12

The browser version in four minutes

Say

This is the simplest way in. Point it at a folder of sounds and every file becomes a cue, in file-name order. That's why file naming matters: 01_Alley_Ambience_loop.wav, 02_Footsteps_gravel.wav.

To put it on a thumb drive: on the website, right-click Open it now ▸ Save link as… and pick the drive. Not Ctrl S: inside TCP that's TCP's own Save. The saved file runs with no internet and doesn't update itself, which is a feature: it stays the same all semester. The handout has the steps, Chromebook included.

Q40:12–0:17

The extension: first run and the storage choice

Say

The first question it asks matters most: where do your shows live?

A folder (on the computer or a USB stick): no sign-in, no internet, never contacts Google. Right for districts where Drive is blocked.

Google Drive: a show follows the student to any Chromebook, from classroom to booth. TCP can only see the files it made, or the ones a student picks for it.

Then building is drag and drop: drop sound files onto the cue list and each becomes a cue, named after its file.

Do

Pitfalls: storage

  • Chromebooks that wipe at sign-out (many shared carts do): a show saved on the computer is gone next class. Use Drive or a USB stick.
  • Drive mode behind a web filter: choosing a file from Drive opens a small page on theatrecueplayer.app, so IT must allow that address along with Google. Everything else still works if it's blocked.
  • Your school's Google admin may need to allow the app to use Drive. Another item for the "ask IT early" list.
If asked early: "Can students work at home?" Drive mode, or take the zip home (Q8).
Q50:17–0:25

The cue list is QLab's vocabulary

Say

GO fires the next cue and moves on. Drill it early: timing is the whole job.

Auto Continue vs Auto Follow is the most common confusion. Auto Continue starts the next cue at the same moment (rain plus thunder together). Auto Follow starts the next cue when this one completes, after all its loops (a chain); an Infinite Loop never Auto-Follows. Same words as QLab.

A fade cue targets another cue: it doesn't play anything itself, it reaches over and changes a cue that's running. "Stop cue when done" is QLab's checkbox too.

Loops (a number, or infinite), hotkeys for instant sound effects, the waveform editor for trims and fade-ins/outs, and Ctrl Z for everything.

Teaching note from your handout: more sound isn't better design.

Screen

"Workshop Demo" show, Edit Mode on.

Do

GO through the Auto Continue pair, then the Auto Follow chain. Add a Fade Cue under the music: it targets the cue above by itself. Set 0% over 3 s, GO it. Show a loop. Fire a hotkey. Open the waveform editor (∿), drag a trim. Undo it.

Pitfall: the old handout's shortcuts

Your Summerfest handout lists browser-version keys. In the extension, F fades the most recent cue (it doesn't open the waveform editor). The extension's keys: Space GO · Esc STOP ALL · Shift+Esc FADE ALL · P PAUSE ALL · Enter play the selected cue · Backspace stop it · E Edit Mode · Ctrl S save · Ctrl Z / Y.

Q60:25–0:29

Running a show safely

Say

Edit Mode off is show mode: the cue list can't be changed by a stray click. Help Mode (the HELP button) locks everything and turns every ? into an explanation. Teach students to look there first.

The panic buttons: STOP ALL, FADE ALL, PAUSE ALL. Once a show is open it works offline, so a dropped network can't stop a performance.

If 2.5.0 is live: GO stays in one place however many cues are playing, and you can hide every column but Cue # and Cue Label and turn the text up to 200%. That's a show display a whole booth can read.

Screen

Demo show, Edit Mode off.

Do

Toggle Edit Mode off. Press HELP, click two ? icons. GO three cues, then PAUSE ALL, resume, then FADE ALL.

Pitfalls: show night

  • Keep TCP's window in front. Chrome slows timers in tabs you're not looking at, so delays can drift if the operator browses mid-show.
  • Set the sound output before the show. TCP plays through whatever the computer is set to; it can't send different cues to different speakers the way QLab can.
  • Sleep off, charger in, notifications off. The same list as your own prep.
If asked: "Could I run a real show on it?" It's built to be dependable, and plenty of schools will. You train on it; you run your productions on professional software when you have it.
Q70:29–0:35

Video and projection in six minutes (extension only)

Say

Video cues fire from the same cue list as sound. A surface is a shape on the projection that you drag into place by its corners (corner-pin warp, like QLab), and masks hide what shouldn't spill onto the set. Text cues do titles, supertitles and credit rolls.

Output to Second Screen is the clean, full-screen projector output, black between cues. Drag it onto the projector and press F.

The Tools page helps with the files: trim a video, pull the sound out of a video, make a title slate.

Screen

"Workshop Video" show, then Surface Setup, then Open Preview.

Do

Video ▸ Enable Video. Open Surface Setup and drag a corner. Close it. GO the video cue, then the text cue. Open Preview to show what the projector would get. Don't demo real second-screen output unless you have a second projector: your room projector is showing your laptop.

Pitfalls: video files

  • H.264 MP4 plays. HEVC and .mkv often don't: TCP shows an amber warning in the cue's inspector. Convert them first.
  • Phone videos can look dark on a projector (HDR). The "HDR fix" setting on the cue corrects it; Auto is almost always right.
  • 4K and 60 fps stutter on Chromebooks. Export close to 1080p. Show ▸ Memory & Resources says which files are too heavy.
  • The projector must be an extended display, not mirrored, or the output window has nowhere to go.
  • Free this year; from August 2027 second-screen output carries a fee and a watermark until paid. Audio-only shows stay free. It never blocks a show.
Q80:35–0:38

Saving, sharing, backups

Say

It saves as you go. Every time a show opens, TCP keeps a copy of the cue list, the last 20, so "go back to how it was yesterday" is Show ▸ Restore from Backup.

Save Show As makes a complete copy with its own sounds: next year's show from this year's. Export Project to Zip is the turn-in format: the cue list plus every file, in one file. Cue sheets print as a PDF or go to a Google Sheet for the stage manager.

Screen

Show menu, then Export menu.

Do

Open Restore from Backup to show the list (then cancel). Show Export Project to Zip.

Pitfall: copyright

From your handout: students list every sound's source in a README inside their zip. If they can't confirm the license, they can't use it. Freesound, BBC Sound Effects, Pixabay and ZapSplat are good places to start.

Two ways to run it

Chrome extension

The full thing: audio, video, projection mapping, text cues, second-screen output, a sound editor, cue list backups, optional Google Drive. Install from the Chrome Web Store.

Browser version

Audio only, nothing to install. Runs from a link or a USB stick, with no admin rights and no internet. Works where extensions are blocked.

Both free for the 2026–27 school year. After that, only second-screen projection output carries a fee. Audio-only shows stay free.

Ask IT before the unit

  • Extensions: managed Chromebooks often block installs. IT can allow or push the extension from the Google Admin console.
  • Google Drive mode: allow theatrecueplayer.app through the web filter, and the app in Google Admin.
  • Chromebooks that wipe at sign-out lose shows saved on the computer. Use Drive or a USB stick.
  • USB drives and downloads: some districts block them on student Chromebooks. Check before you plan on thumb drives.

Feature highlights

  • Drag sound files onto the cue list (video and pictures too, in Video mode), and each becomes a cue named after its file. (Browser version: Load Audio Folder, in file-name order.)
  • GO / Spacebar: fires the next cue.
  • Auto-Continue starts the next cue at the same moment. Auto-Follow starts the next cue when this one completes, after all its loops. An Infinite Loop never Auto-Follows.
  • Fade cues target another cue and fade it to a level; "stop cue when done", as in QLab.
  • Loops, hotkeys for instant effects, a waveform editor for trims and fades, and (extension) a Sound Editor that sends the edited sound right back to the cue list.
  • Edit Mode off = show mode. Help Mode explains every control; teach students to look there first.
  • Backups: the last 20 cue lists, one each time a show opens. Export Project to Zip packs the cue list and every file.
  • Video (extension): H.264 MP4 near 1080p. Phone video looking dark? Use the cue's HDR fix.

Take it offline

Browser version on a thumb drive:

  1. On theatrecueplayer.app, right-click Open it now and choose Save link as…
  2. Pick the thumb drive and save. On a Chromebook, the USB drive is in the save dialog's left sidebar.
  3. To run it, double-click the file (on a Chromebook, in the Files app). It opens in Chrome; if another browser opens it, right-click the file ▸ Open with ▸ Chrome.
  4. Keep the sound folder on the same drive and use Load Audio Folder from there.

Sound Design Project

A Theatre Cue Player classroom project · theatrecueplayer.app

Project overview

Students create a complete sound design for an assigned scene, programming intentional cues that support mood, setting, and action, then present and defend their choices to the class.

4-day pacing guide

DayTeacherStudentsDeliverable
1Demo TCP (0–20 min): load sounds, add cues, waveform editor, Auto-Continue, fades, export. Copyright sources overview.Independent exploration + initial cue plan (20–45 min).Cue plan or timeline screenshot.
2Recap. Mini-conferences: check programming & annotations.Place ambient, action, transition cues; set Auto-Continue + Fade. Peer listening pairs.Saved project + updated annotated script.
3Recap. Final check before export (45–50 min).Refine timing, volume automation, file naming. Peer feedback stations.Project ready for export.
4Record rubric scores during runs.Present scene (5–7 min each): run program, readers read lines, explain 3 design + 1 technical choice.Zip submission + peer feedback.
5**Optional overflow.Extra presentations, troubleshooting, or extended peer sharing.—

Required elements

  • 6+ sound cues that justify mood, setting, or action
  • 1 Auto-Continue for ambient/layered tracks across scene beats
  • 1 Fade (in or out), typically 1–8 sec depending on cue type
  • 1 Intentional Volume Change via a fade cue, not just clip gain
  • Annotated script: cue labels match file names; include start, stop/fade, volume notes
  • Zip submission: project file + audio files + annotated script + README.txt with source credits

Script annotation format

[SFX 2: Thunder_Heavy.wav — start at line 3; fade out 4s after line 6; vol -3dB] "He looked up at the sky."

File naming convention

01_Alley_Ambience_loop.wav
02_Footsteps_gravel.wav
03_Door_squeak_fadeout.wav

Formative check questions

  • Which moment needs a sound cue, and why?
  • Where will you use silence for effect?
  • Show me where Auto-Continue, Fade, or Volume Change appears in your cue list.
